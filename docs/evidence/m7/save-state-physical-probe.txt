M7 save-state-assisted physical probe
Date: 2026-07-31
Scope: temporary developer-only device validation

Result

The temporary app-private save-state route is usable for M7 investigation:

- a castle-grounds checkpoint loaded without repeating the title, file
  selection, or intro sequence;
- a second checkpoint loaded at the castle-entrance approach;
- physical Touch Mode movement changed the playable castle-grounds scene on
  the external Thor display after ThorDS was restored to the foreground;
- no ThorDS crash or ANR was observed during the checkpoint and movement
  probes.

The route is not an M7 acceptance pass. No FOV, culling, HUD, or transition
measurement was produced. The user-visible top screen was reported as
physically rotated 180 degrees relative to the internal capture orientation;
the Thor-specific product default now produces the same inverted logical
castle-grounds capture on the primary surface without a rotation extra, while
leaving the lower presentation unchanged. This proves the app-side transform
path; the final physical orientation still needs direct verification before
the M7 gate can close. Per the repository owner's scope correction, castle
grounds is the M7 representative scene; no Bob-omb Battlefield route is
required for the gate.

Device contention

During the probe, the separate `dev.picori.tmc.ra` test application reclaimed
the foreground and silently received subsequent physical touch events while
ThorDS continued rendering. Stopping that test application and restoring
ThorDS to the foreground restored the expected input path. This was a
temporary device condition; no source or product configuration was changed.

Safety

The ROM, save states, renderer captures, logs, and device-specific temporary
files remained outside the repository and were removed after the probe. No
private capture or ROM-derived data is part of this evidence file or Git
history.
