M7 debug input harness result, 2026-07-31

Change:
- debug-only TAP_INPUT accepts only existing DS system buttons:
  A, B, X, Y, L, R, Start, Select and D-pad
- it calls the existing MelonEmulator input-down/input-up path with a bounded
  press duration
- it does not alter controller configuration, profile behavior or release APKs

Physical Thor validation:
- debug APK installed successfully
- active ASMP debug session logged repeated TAP_INPUT Start and A commands
- no ThorDS FATAL or ANR was observed during the command sequence
- the sequence did not reach a deterministic castle-grounds checkpoint, so no
  gameplay or True Widescreen acceptance result is claimed

Execution note:
- Android may reject an implicit debug broadcast while the receiver is not
  foreground-eligible. The verified harness route targets
  `DebugCommandReceiver` explicitly with `adb shell am broadcast -n`; it
  returned `success=1` and emitted the corresponding DebugCommand log.
- Accepted debug touch input alone did not provide a deterministic
  title-to-castle-grounds route. The separate save-state route is used for M7
  scene efficiency; physical orientation and gameplay measurements remain
  required for the M6 and M7 gates.

Temporary ROM copies, saves, frame images, metadata and log output were deleted
after validation. No ROM path, ROM bytes, save, capture, device identifier or
credential is retained here.
