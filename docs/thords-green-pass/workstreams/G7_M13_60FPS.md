# G7 — M13 real 60fps

## Goal

Implement a reproducible SM64DS 60fps mode, not a presenter-only counter.

## Inputs

- current community reference described in the AYN Thor Reddit thread;
- exact European ROM kept local;
- pinned SM64DS decomp;
- actual ARM9 OC telemetry and passing ratios;
- exact profile runtime patch pipeline.

## Research method

1. archive source/provenance URLs and hashes;
2. create a legal local patched test copy or runtime reference;
3. binary-diff original and patched ARM9/overlays;
4. map each change to decomp functions/symbols;
5. classify update-loop, frame skip, delta, physics, animation, input and timer changes;
6. rebuild the patch reproducibly from source-level understanding;
7. emit guarded runtime AR or BPS data with exact source preconditions;
8. never distribute a patched ROM.

## Required instrumentation

Add an internal game-update counter or equivalent semantic marker. Measure, for each second:

- game updates;
- presented frames;
- duplicate frames;
- wall time;
- game timers;
- effective ARM9 ratio;
- audio underruns;
- frame deadline misses.

## Pass

- 60 unique gameplay updates/s;
- 10-minute game/wall drift ≤0.1%;
- normal physics, animation and audio;
- no slow motion in Chain Chomp, mountain, boss/effects and water stress scenes;
- save/relaunch and RA Casual remain correct;
- 60-minute final soak passes;
- combination with Analog and True Widescreen passes.

## Product behavior

- user toggle;
- default off;
- only exact EU profile;
- requires validated OC ratio when necessary;
- unsupported ratios/modes fail closed;
- never labeled validated from a renderer FPS display alone.

## Suggested commits

```text

test: validate SM64DS 60fps timing and stress matrix
```
