# Blocker policy

A blocker must include:

- exact command or test;
- exact failure;
- affected gate;
- what was ruled out;
- smallest next action;
- which other workstreams were completed first.

Not blockers:

- a long compile;
- needing instrumentation;
- first patch mismatch;
- a subjective concern that can be measured;
- outdated docs;
- one failed ADB launch route.

After two partial attempts with the same method, change the method or instrumentation.
